# Vim conformance matrix

This is a test inventory for the behavior specified in [PRODUCT.md](PRODUCT.md) §4.3, §20.2, and §23. It does not define additional Vim behavior. “Covered” means that the named automated tests exercise the stated case; it does not claim that every possible key sequence is tested. The navigation dimensions follow [DEVELOPMENT.md](DEVELOPMENT.md) §8. A clause tagged `matrix-only (Mn)` states behavior that PRODUCT.md does not state; it waits for a Product Owner decision (see Open matrix-only rules below) and is not a requirement.

**Vim divergence.** A row marked **Vim divergence** states a behavior that deliberately differs from what Vim does for the same Normal-mode key or command; the reason after the marker explains the deliberate application model. The rest of a marked row remains a claim about Vim. A row without the marker is expected to match Vim for the keys and commands it names, so an unmarked divergence is a defect. Vim has no attachment or node tree: a row that names a Vim key is compared with Vim's result for the same keys applied to the node's text (and, for node commands, to the node tree), so behavior that reaches the attachment departs from Vim. A row without the marker is not a conformance claim when it describes only application mechanisms with no Vim key or command (application modifier shortcuts, pointer, blur, focus, and session bookkeeping, persistence and quit behavior, unsupported keys, and test coverage rows), or when it describes only the attachment's own caret state (an image caret, a saved return position, or an image-only node).

Who decides a divergence is recorded in [AGENTS.md](../AGENTS.md) §5 (Vim divergences).

## Agenda

Agenda direct matches reuse Tree text commands. Normal `Enter` opens the hyperlink or image under the caret without creating a node (PRODUCT §23.10); handler regressions in `src/renderer/editor-input-handlers.test.ts` and “Normal Enter opens links and images without splitting or leaving Agenda” in `e2e/agenda-vim.spec.ts` cover it. `src/renderer/agenda-command-matrix.test.ts` exercises every Command Matrix row on all applicable element kinds through the actual keyboard handlers. Agenda structural command restrictions are also covered by `src/renderer/agenda-key-policy.test.ts` and `e2e/agenda-editing.spec.ts` under PRODUCT §23.10; Normal `o`/`O` on a day container create a dated node under PRODUCT §23.11, covered by `src/renderer/agenda-row-keyboard.test.ts` and the same E2E spec; Normal `o`/`O` on a direct match create a dated sibling under the same section, covered by `src/renderer/editor-input-handlers.test.ts` and `e2e/agenda-vim.spec.ts`; contextual and synthetic rows never enter text editing, but their displayed text has a read-only caret, character Visual selection and yank under PRODUCT §23.4, covered by `src/renderer/agenda-row-text-keys.test.ts` and `e2e/agenda-caret.spec.ts` (“moves, selects and copies over the text of a day without editing”). Agenda folds and navigation affect the projection independently of Tree. Vertical navigation carries the caret through noneditable rows and uses Tree's attached-image transitions, covered by `src/renderer/agenda-row-keyboard.test.ts`, `src/renderer/agenda-row-keyboard.property.test.ts`, “carries the caret through a day and contextual ancestor into another editor” in `e2e/agenda-caret.spec.ts`, and “vertical navigation enters and leaves images and preserves a clamped image return position” in `e2e/agenda-vim.spec.ts`.

## Inapplicable combinations

The following matrix combinations are intentionally inapplicable under the specified behavior: `h` does not enter an image from text; `l` does not leave an image for another node; an image-only node has no text position to restore; and text operators/character Visual selection do not extend across the image or into another node. No broader Vim compatibility is inferred from the command names.

## Generated interaction guards

The bounded mixed-sequence guard in `src/renderer/vim-mixed-interaction.property.test.ts` compares the production keyboard handler and `EditorStore` with an independent expected-state model after each generated event. Its fixed seed covers counted motions and replacements, empty and image-only roots, cross-node and boundary motion, pointer focus, count interruption, text deletion, and undo/redo including edit-after-undo. A named deterministic regression and a real-Electron case assert one undo per standalone text replacement; `src/application/editor-store.test.ts` also guards 120 standalone edits near the history limit. The fast generated suite uses 80 runs of at most 22 events over at most four short nodes. Its generated history events never arrive with a command pending, because every generated event assembles and consumes its own count and the model asserts an empty pending slot after each step; the unfinished-command rows above therefore carry focused and Electron evidence instead.

`src/renderer/use-node-input-bindings.property.test.tsx` runs the same independent model (`src/renderer/test/vim-sequence-model.ts`) through the production `useNodeInputBindings` hook and a real `EditorStore`, so the hook's focus effects, deferred projection, and command handlers apply the caret instead of the test. It queues the hook's microtask work and flushes it after some events only, asserts the DOM cursor, image indicator, mode, and focus after each event and again after a flush, and probes the next command with `Enter`, which must open the image preview exactly when the model has the image active. The hook regression “advances the caret after replacing characters with themselves” covers a Normal text command that leaves the text unchanged. The suite uses textarea inputs only, takes native pointer placement from a synthetic mouse event, and moves between nodes through the store's focus intent, so the Electron image and text-editing specs keep the native focus, pointer timing, contenteditable, and rendering evidence.
