# Vim conformance matrix

This is a test inventory for the behavior specified in [PRODUCT.md](PRODUCT.md) §4.3 and §20.2. It does not define additional Vim behavior. “Covered” means that the named automated tests exercise the stated case; it does not claim that every possible key sequence is tested. The navigation dimensions follow [DEVELOPMENT.md](DEVELOPMENT.md) §8.

## Interaction-state contract

This contract makes the existing [PRODUCT.md](PRODUCT.md) §20.2 behavior and its focus/caret test expectations explicit. It does not add commands or change state ownership. A transition's observable state is the selected node, Vim mode, focused input, text selection or image caret, and (when an image was entered from text) the text position to restore. The store's focus intent has a node ID, cursor, and monotonically new token; the token distinguishes an intentional focus request from an unchanged store focus after a local caret motion. The selected node ID alone cannot make that distinction.

| State or event | Contract |
| --- | --- |
| Normal text and image caret | Exactly one caret is active on the selected node. Text positions are character indices, with a block selection on the current text character. An attached image is the terminal character at `text.length`; on an image-only node, index `0` is the image and there is no text position to save. |
| Saved image return position | Same-node `j` from text and `l` from text into the image save a valid position in that node's text. `k` or `h` from the image restores it, with a remaining count applied for `h`. An in-node move to text, edit that lands on text, or cross-node move clears it. It never belongs to another node. |
| Focus intent | A successful store navigation, history operation, structural operation, or explicit selection supplies a fresh focus token, including when the selected node ID remains the same. The renderer applies its target cursor to focus and derives the image caret from the target node and cursor, superseding an older saved return. Local character motion changes the caret without a store focus request; an unchanged token must not replay an older focus cursor over it. |
| No-op and clamped transition | An unavailable undo, redo, or leave and whole-node Visual entry followed by exit without movement produce no new focus intent, so the active image caret and saved return position survive. A failed in-node search leaves the caret in place. A level-boundary motion can explicitly reselect the same node with a new focus cursor; it must apply that cursor even though the node ID is unchanged. Clamped `k` on an image-only first root retains its image caret, while a whole-node Visual clamped move selects cursor `0` and clears a prior text-plus-image caret. |
| Modes and pointer input | Normal uses the text block or image caret; Insert and Replace use the thin text caret; character Visual and whole-node Visual own their selections. Escape and Visual exits resume Normal at the documented cursor. Pointer focus/selection preserves the current Vim mode and places the text caret at the pointer-selected position; leaving an image through pointer input drops the old saved return. A pending Replace edit is committed before an application history shortcut is applied. |

The store owns location and focus intent; the renderer owns mode, DOM caret/selection, image-caret indicator, and saved image return position. This is a characterization of the current architecture for the VIM-2 tests, not an implementation of the later transition model. Focused coverage for token-sensitive no-ops and same-node requests is in `src/application/editor-store.test.ts` and `src/renderer/use-node-input-bindings.test.tsx`; the rows below map representative Electron behavior.

## Image and caret transitions

The recorded text position belongs to the active node; a cross-node move uses the destination position determined by navigation. The navigation gaps closed earlier were the image-only horizontal/boundary and two-way vertical transitions, a counted move that crosses an image row before changing siblings, and pointer exit from an image state. The edit-to-caret rows above cover the subsequently found mutation gaps. History and current-parent boundary commands (`u`, `Ctrl+r`, `Ctrl+o`) closed a later-found gap, entering a childless attachment-bearing node (`gd`, `Cmd+.`, its enter control, or an ancestor breadcrumb click) closed the next gap, and whole-node Visual mode's own moves and mutation commands closed another gap: each changed focus without resyncing the image-caret indicator. The remaining no-op path gap was caused by resynchronizing from an old store focus intent after local image motion; only a new focus token now supersedes that local caret. Search, named registers, macros, and marks are explicitly unsupported by PRODUCT §20.2 and have no conformance rows.

The following matrix combinations are intentionally inapplicable under the specified behavior: `h` does not enter an image from text; `l` does not leave an image for another node; an image-only node has no text position to restore; and text operators/character Visual selection do not extend across the image or into another node. No broader Vim compatibility is inferred from the command names.
