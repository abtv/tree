# Vim conformance matrix

This is a test inventory for the behavior specified in [PRODUCT.md](PRODUCT.md) §4.3 and §20.2. It does not define additional Vim behavior. “Covered” means that the named automated tests exercise the stated case; it does not claim that every possible key sequence is tested. The navigation dimensions follow [DEVELOPMENT.md](DEVELOPMENT.md) §8.

## Image and caret transitions

The image is character index `text.length`. For image-only text, index `0` is the image. The recorded text position belongs to the active node; a cross-node move uses the destination position determined by navigation. These are the states required by DEVELOPMENT §8, with directly relevant evidence.

| Source and entry | Expected destination or exit | Automated evidence |
| --- | --- | --- |
| Text beginning/middle/final, `l` or counted `l` | Advance to the terminal image, clamped at it; an oversized count retains the final valid text position for `h` | `src/renderer/vim-editing.test.ts`: “Vim image character positions”; `src/renderer/vim-editing.property.test.ts`: “records a valid final text position”; `src/renderer/editor-input-handlers.test.ts`: “restores a valid text character after an oversized counted l”; `e2e/vim-editing.spec.ts`: “navigates between text and its image”, “returns to text after an oversized counted l” |

The navigation gaps closed earlier were the image-only horizontal/boundary and two-way vertical transitions, a counted move that crosses an image row before changing siblings, and pointer exit from an image state. The edit-to-caret rows above cover the subsequently found mutation gaps. History and current-parent boundary commands (`u`, `Ctrl+r`, `Ctrl+o`) closed a later-found gap, entering a childless attachment-bearing node (`gd`, `Cmd+.`, its enter control, or an ancestor breadcrumb click) closed the next gap, and whole-node Visual mode's own moves and mutation commands closed the most recently found gap: each changed focus without resyncing the image-caret indicator. Search, named registers, macros, and marks are explicitly unsupported by PRODUCT §20.2 and have no conformance rows.

The following matrix combinations are intentionally inapplicable under the specified behavior: `h` does not enter an image from text; `l` does not leave an image for another node; an image-only node has no text position to restore; and text operators/character Visual selection do not extend across the image or into another node. No broader Vim compatibility is inferred from the command names.
