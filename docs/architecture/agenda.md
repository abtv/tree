# Agenda

### 4.1 Agenda Projection

`agenda-projection.ts` derives day groups of node identifiers, scoped depths, and match/context roles from the immutable document. The application consumes it through `agenda-rows.ts`. Direct and subtree date sets are memoized in a weak map keyed by `TreeNode`; path copying invalidates only replaced nodes, so date recognition after an edit reuses unchanged branch summaries. A subtree shares its direct set until a descendant contributes a new day, at which point it copies before adding that day. Row generation visits relevant branches once for all days that need fresh rows, and a day whose branches are unchanged from the previous projection keeps its previous row array. The cache stores day sets rather than flattened row copies, permits collection with its node keys, and has no persisted fields or disk operations.

### 7.3 Agenda Store

#### 7.3.1 State, Rows and Cache

The Agenda store uses `agenda-state.ts` for pure runtime transitions and `agenda-rows.ts` to derive the displayed Monday–Sunday week, including empty days, flatten direct matches, and insert one keyed separator before each day after the first. The domain projection retains ancestor identities; application rows add read-only parent paths before consecutive matches with the same parent. Separators carry only their following day and occurrence key; selecting one makes activity inactive and never selects a document node. `EditorStore` owns one row cache and publishes real-node selection with location and focus atomically. Rows carry node IDs rather than captured node content, so unchanged date membership can reuse their identities while the document supplies current text. Presentation is an explicit `timeline` or `focused-day` union; the latter requires its day and captured timeline selection, week, day-fold references and scroll anchor. Focused folds use a separate set. Activity is independently `inactive`, `dated`, or `pinned-until-leave`, with one occurrence descriptor for either active state. Selection can name a node without activating its editor after timeline return. `isEditableOccurrence` in `agenda-rows.ts` decides whether an occurrence owns an editor (PRODUCT.md §23.9), from the row's role, the active occurrence and the days of the node, including Today for a mark (PRODUCT.md §2.7). `agenda-reconcile.ts` resolves date loss, restoration and migration through this activity state. Live date migration updates the focused day while retaining captured return data; history preserves presentation. Cache selectors return the original pinned descriptor to preserve identity-based reuse. See [ADR 0020](../decisions/0020-agenda-derived-projection-and-runtime-view-state.md), amended by [ADR 0030](../decisions/0030-persisted-agenda-fold-choices.md) for explicit fold choices.

Runtime publication, history reconciliation, and renderer reads share that store-owned cache. It preserves semantically unchanged projected day objects. Its per-day row cache reuses a day's node row objects while that day's projection remains unchanged; the row build uses it for the days of the displayed week in the timeline presentation and for the day of the focused-day presentation. Day folds determine which fragments enter the visible list; fragments contain no fold-dependent content. A date edit that affects one day therefore does not allocate fresh node rows for the unchanged days that use the per-day cache. The Overdue group does not use it: a row build that includes the group creates the group's node rows again, and creates its parent-path rows only when the group is expanded. The per-day fragments contain identities and row references, never document nodes, and are pruned when projected days disappear. Closing Agenda retains the latest cache for reopening the unchanged document; publication in Tree releases it when the document changes. Fold membership, rather than a new Set object's identity, determines whether a fresh opening can reuse its rows. Their storage is bounded by the latest projected rows and folds, rather than the edit count. Standalone reconciliation helpers can run without a cache. The cache reduces repeated interactive projection and allocation and causes no disk writes, syncs, or history snapshots; full projection and comparison still scale with dated occurrences and contextual ancestors.

Performance assessment for Agenda state (PRODUCT.md §22.1): opening, selection, focused presentation changes and focused-day folds cause no document writes or syncs. An explicit timeline fold command marks a persisted change for the save scheduler only when it changes the remembered timeline choice (§8.1.5). None of these adds an undo snapshot. Saves already pending capture the Tree origin location and viewport while Agenda is active. Today is sampled once on open. With Agenda closed, runtime publication does no projection work and checks the retained document identity in constant time. With it open, projection reuses immutable-node date summaries; a text edit rescans the changed path, but projection and semantic comparison still scale with dated occurrences and their ancestors. The row build runs only when that projection, Today, the displayed week, day folds, the focused day or the active occurrence changes, or when the document changes while the projection holds a day before the displayed week, because the Overdue group reads each node's finished state from the document. After a row build, the cache keeps the previous row array only when the projection is unchanged and the built rows compare equal; otherwise it publishes the new array. One store cache retains only its latest document and projection; a document replacement in Tree releases them, while domain summary caches have weak keys. The saved timeline state is bounded by existing day folds rather than the number of edits and is released on return or close. Application guards use wide dated documents to assert a single rescan, stable row-array identity after a same-date keystroke, and cached row reuse during focused navigation and repeated view switching.

#### 7.3.2 Entry into Tree

`EditorStore.enter` resolves Agenda's selected row from its cached rows, then publishes the destination Tree parent, selection and focus together while removing Agenda. The cached-row lookup also supports a selected occurrence without an active editor. This transition never restores the captured Tree origin; `closeAgenda` owns that separate operation. Entry from Agenda performs one lookup over the cached visible rows and then uses the indexed node transition; it retains no state. It follows the navigation save policy: the new location marks a persisted change for the idle autosave, with no other write or sync.

#### 7.3.3 Clipboard Transitions

Agenda clipboard transitions normalize native line endings within one node and remap hyperlink endpoints using sorted CRLF positions. Normalization costs O(text length + link count × log(CRLF count + 2)); its temporary index is released after the paste. Image paste checks the current Agenda and attachment again after asynchronous writes, so concurrent completions cannot create a sibling. Discarded image writes use the attachment cleanup. These rules use no persistence fields, syncs or background state of their own.

### 8.1 Agenda Rendering

#### 8.1.1 View, Rows, Keys and Editing

`AgendaView.tsx` renders the store's derived Agenda rows instead of the Tree heading and list. Rows use occurrence keys and `.agenda-row`; editable occurrences use stable real-node React keys so date migration preserves the mounted input. Direct matches reuse `NodeInput` and the shared input hook. The view mounts an input, draws the synthetic caret and routes row keys according to `isEditableOccurrence` (§7.3.1).

The pure `agenda-key-policy.ts` table gates command families; shared editor and Vim handlers intercept structural commands before Tree dispatch. Row navigation and Agenda folds live in `agenda-row-keyboard.ts` and share the hook's Vim command-state owner. Rich date spans preserve plain character offsets and link ranges.

A selected row without an editor (day, parent path, separator, mirror, or focused-day heading) has no native text control, so its caret and selection are renderer-local state. `agenda-caret-state.ts` owns the selected synthetic row's offsets, `agenda-row-caret.ts` computes the marks drawn in its text, and `agenda-row-text-keys.ts` applies the caret motions, Visual selection and copy that `agenda-row-keyboard.ts` routes to it. `AgendaView.tsx` retains one state for the selected occurrence. Navigation supplies an explicit arrival offset through runtime-only `AgendaState.selectionCursor`; pointer selection of another noneditable row starts at zero.

Normal vertical navigation reuses `verticalCaretTransition` and `focusCaretTransition` to resolve attached-image steps, saved text return positions, destination clamps and counted motions, publishing the resolved editor caret through the input hook's authority. Clamped vertical motions publish no new selection or focus intent. Local text motions never reach the store, document or persistence, and copying uses the `copyVimContent` clipboard service.

Performance assessment (PRODUCT.md §22.1): a local motion costs O(row text) and re-renders the selected row; it writes nothing and publishes no snapshot. Navigation retains one arrival offset and uses the row lookup; counted motion performs bounded per-step caret transitions. Agenda row navigation causes no disk writes, syncs or history entries and retains no unbounded memory; the Agenda navigation performance guards cover this path.

The hook reveals Agenda rows and restores pending carets through the same owner as in Tree. Tree scroll restoration and viewport-save listeners suspend during Agenda; closing issues a fresh Tree focus intent. Date labels use domain calendar arithmetic rather than timezone-sensitive formatting.

Live mirrors are derived in the renderer by `isAgendaMirror` from the active occurrence (`activeAgendaOccurrence`) and drawn as the `agenda-mirror` row class; they mount no input. When a document change re-derives the rows (a new row array) and the active node's occurrence moves, `AgendaView` measures the selected row's viewport top from a store subscription, which runs before React renders and mutates the DOM, and corrects the scroll by the difference after the commit, skipping viewport reveal for that commit. Pure selection changes never publish a new document and take no adjustment, and a keystroke that keeps the same rows does no measuring. The transient status message is derived from the store state by `agendaStatusMessage`; the status bar renders it only while it exists, so Tree layout and the Tree live regions are unchanged.

Agenda editing reuses document history, clipboard operations and persistence scheduling. Decoration work is bounded by mounted rows and each node's text; it causes no disk write or sync. Unmounted rows release their input and geometry references.

Agenda edits existing nodes only. Enter and multiline clipboard text route through a single-node range replacement, preserving links and ordinary text history. A trailing BR sentinel lets Chromium retain a rich editor's final newline without adding a text character. Keyboard and store guards prevent node creation, deletion, node-register puts and moves; image paste rejects a second-image sibling, and OCR cannot create nodes in Agenda. Whole-node Visual and Agenda drag adapters are absent; Tree retains its own structural commands.

#### 8.1.2 Caret State and Text Geometry

`agenda-caret-state.ts` owns the Agenda occurrence/focus handoff as native or synthetic state. Only synthetic rows retain local selection offsets; native text and image caret authority stays in `caret-projection-state.ts`. Occurrence keys and focus tokens reject stale arrivals and scope preservation of the shared command owner's desired X. Find reads synthetic offsets locally and delegates active native rows to the input owner. A selected but inactive native row has not consumed its published focus intent, so Find reads that arrival cursor without activating the row or storing a second native caret. `AgendaView` projects this state without publishing same-row motion to the application store.

`agenda-text-geometry.ts` measures mounted and temporary windowed rows from the same text axis. It removes editor padding from measured horizontal positions because synthetic day labels use a margin instead. Desired X can therefore cross entries, empty separators and day headings without accumulating an offset. The padding correction reads only the measured row's style and retains no state.

#### 8.1.3 Viewport State

`agenda-viewport-state.ts` owns Agenda opening, navigation and pending geometry intent. End tracking, captured edit anchors and timeline restoration are orthogonal, so measurement can settle them without discarding valid concurrent intent. Native scroll delivery and external resize notifications capture end tracking before mounting newly visible rows can increase the estimated extent, including resize after an end jump but before scroll delivery. Geometry reads after measurement compensation preserve that intent. Opening Today precedes line delegation, anchoring and ordinary row reveal; a synthetic local-line request is consumed after row effects. The shared `viewport-reveal.ts` executor retains geometry, listeners and deliberate-scroll cancellation. Anchor capture happens before React mutation, and correction waits for measured rows and revision. All transient intent is bounded by the current view rather than motion count.

#### 8.1.4 Parent Paths

Agenda parent paths are synthetic read-only rows in the application row projection. Consecutive matches with the same parent share a path row, without reordering occurrences. Path identities reuse the day-row cache, except in the Overdue group, whose path rows follow the rule in §7.3.1; the renderer resolves current ancestor labels through the document index only for displayed or measured rows. Paths use the synthetic caret, selection, folding reconciliation and window measurements, without creating editors, document changes, saves or syncs. The cached memory of paths is bounded by the projected path groups. Global Search (§13.3) stores the parent ID with each nested result. Its session tracks whether selection targets the node or its group heading and passes the corresponding ID to the store on activation.

Parent paths are presentation rows only; `AgendaRowsCache` supplies a match-only projection to local search.

#### 8.1.5 Fold Memory

`AgendaFoldMemory` owns explicit timeline fold choices for the store lifetime, separately from the effective `AgendaState.collapsed` presentation. Opening Agenda shares its immutable set; closing Agenda or entering Tree retains it. The application records only the targeted populated day rows after an explicit timeline fold command. It records the resulting membership rather than toggling the saved choice, because search may have temporarily opened a remembered fold. Search and live-edit reveals never write this owner. Focused-day folds remain independent and temporary; returning restores the captured timeline set. History does not own these choices. A changed choice marks the save scheduler pending, including while locked, without restarting locked automatic saves.

Performance assessment (PRODUCT.md §22.1): remembered folds occupy O(F) space for distinct closed dates and Overdue weeks within the supported calendar range, not per edit or history entry. Opening and ordinary navigation reuse the set without traversing F. Explicit fold changes copy the immutable set and rebuild its numeric snapshot in O(F), without scanning the document; repeated no-op choices add no pending save. Serialization normalizes O(F) numeric values during saves. There is no separate file, write or sync per fold: rapid choices coalesce under the idle, volume and quit triggers (§13.8). Scale guards exercise remembered dates outside the visible week, stable opening/selection references, coalesced writes, in-flight saves and the locked final flush.

#### 8.1.6 Windowing

Agenda windowing reuses `list-window.ts` and the key-based layout helpers in `node-list-layout.ts`. `agenda-list-layout.ts` selects the viewport range and optional selected row pin, including separators. Heights and DOM elements are keyed by occurrence, not real node id; row changes prune obsolete measurements and width changes invalidate them. Cached offsets rebuild on row or measurement changes, while selection and scrolling reuse them. Headings, separators and node entries each own a measured wrapper. The selected keyed row remains in the same React parent when switching between the viewport and absolute pin; layout notifications let the viewport-reveal owner settle its position after measurement. On opening, that owner accepts one live region covering the complete Today block; its bounded observers correct layout settlement until user input cancels the intent. The mount layout effect reinstates the region during development StrictMode effect replay. Oversized blocks reveal their beginning, and natural scroll limits clamp centering. Opening alignment uses no document traversal per correction, no extra scroll owner, and no persistence or history.

Agenda gives the windowed list its measured total height and places mounted rows in a zero-height sticky anchor. An inner offset positions that window relative to the last committed viewport. Native scrolling can present a new scroll offset before delivering its scroll event; the anchor keeps the previous painted rows visible during that interval. The scroll listener synchronously commits the new rows and their offset together. Only the scroll event commits synchronously; layout-effect and resize updates keep their ordinary commit order. The selected occurrence stays in the same React parent, with its pin positioned relative to the window origin. The list clips overflow so a pending window cannot extend the scroll range at the timeline end. The sticky anchor uses no document writes, syncs, retained row copies or animation-frame polling. Scroll rendering is bounded by the mounted window; offset rebuilds on new height measurements scale with projected rows and are covered by the Agenda scale performance suite.

#### 8.1.7 Held View Shortcuts

`use-agenda-repeat.ts` paces held Tree/Agenda shortcuts in the renderer. First and separate presses use their ordinary handlers. Autorepeat retains one pending switch and one animation request; two animation callbacks leave an intervening rendering opportunity before another view replacement. The callback uses the session-preparation and store commands, with no synthetic keyboard events. Release, window deactivation, composition and other input cancel pending work. Pacing keeps constant session memory and performs no document traversal, disk writes or syncs of its own. A rendering opportunity is not an acknowledgment that pixels reached the display; native held-input regression coverage checks command cadence, focus and cancellation separately from visual acceptance.
